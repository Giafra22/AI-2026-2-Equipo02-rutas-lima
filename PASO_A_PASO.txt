2. INSTALAR PYTHON (SI AÚN NO LO TIENEN)
1) Ir a https://www.python.org/downloads/windows/
2) Usar Python 3.12 para mantener la misma versión local y de publicación.
   El proyecto utiliza sintaxis compatible con Python 3.10 o superior.
3) En el instalador marcar Add python.exe to PATH si aparece y completar
   la instalación. Si ya tienen Python 3.12, no es necesario reinstalarlo.
4) Cerrar y abrir otra vez la terminal si estaba abierta.
5) Verificar en CMD: py --version
   Si py no existe pero python sí, usar python en lugar de py en el paso 3.
No es necesario instalar Git ni NetworkX para este flujo.

3. ABRIR CMD DENTRO DE LA CARPETA CORRECTA
1) Abrir en el Explorador la carpeta donde está app.py.
2) Hacer clic en la barra de dirección, escribir cmd y pulsar Enter.
3) Se abre CMD con esa ubicación. Escribir: dir
4) Comprobar que aparecen app.py, graph_data.py, algorithms.py y
   requirements.txt. Si solo aparece otra carpeta, entrar en ella y repetir.
Usar CMD para estos pasos: así no hace falta cambiar permisos de PowerShell.

4. CREAR EL ENTORNO E INSTALAR
Ejecutar estas líneas una por una, pulsando Enter después de cada una:

py -3.12 -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe verificar_proyecto.py
.venv\Scripts\python.exe -m streamlit run app.py

Si Python 3.12 no está instalado pero tienen otra versión compatible:
reemplazar solamente la primera línea por: py -m venv .venv
Si no tienen el comando py: python -m venv .venv

Esperar que termine cada comando. La instalación requiere Internet.
La verificación debe mostrar OK: 2000 escenarios origen/destino.
La última línea abre la app. Si no abre sola, entrar a http://localhost:8501
Mantener CMD abierto mientras se usa la app. Para detenerla: Ctrl+C.
En las siguientes sesiones pueden hacer doble clic en INICIAR_WINDOWS.bat,
o repetir solamente la última línea. No reinstalar en cada sesión.

5. PROBAR EL EJEMPLO PRINCIPAL
Dejar los controles así:
Origen: Santa Anita
Destino: Miraflores
Ruta que se dibuja: A*
Conexión bloqueada: Ninguna
Corridas por técnica: 100

Resultados esperados de distancia:
Ruta base: 23 km, 0 nodos expandidos.
BFS: 23 km, 9 nodos expandidos.
DFS: 49 km, 9 nodos expandidos.
A*: 20 km, 8 nodos expandidos.

A* elige Santa Anita > San Luis > San Borja > San Isidro > Miraflores.
Suma: 6 + 4 + 6 + 4 = 20 km.
La base usa Santa Anita > Ate > La Molina > Surco > Miraflores.
Suma: 4 + 6 + 7 + 6 = 23 km.
Ahorro: (23 - 20) / 23 * 100 = 13.0% aproximadamente.

Los tiempos serán distintos en cada equipo y cada ejecución. A* puede ser
más lento en este grafo pequeño porque calcula heurísticas y usa una cola
de prioridad. El objetivo principal aquí es reducir la distancia, no asegurar
el menor tiempo de procesamiento.

Comprobar además:
a) Cambiar Ruta que se dibuja a BFS y DFS: se actualiza la ruta en el mapa.
b) Bloquear Santa Anita ↔ Ate: la base queda sin ruta, los buscadores pueden
   encontrar alternativas. Mostrarlo como diferencia frente al itinerario fijo.
c) Cambiar origen y destino a Santa Anita: distancia 0 y expansiones 0.
d) Cambiar destino a San Borja y después a San Isidro.
e) Cambiar corridas a 500 y pulsar Recalcular comparación.
f) Descargar comparación CSV y abrirlo para comprobar su contenido.
g) Restaurar el ejemplo principal antes de la exposición.

LO QUE REPRESENTA ESTE AVANCE
- Una entrega entre un origen y un destino en un grafo de 10 puntos.
- Distancias simuladas en km, conexiones bidireccionales y costos positivos.
- Prioridades y tráfico real no están implementados.
- No usa mapas externos ni GPS, y no representa calles reales.
- No resuelve el orden óptimo de múltiples entregas (TSP).
- Parte 2 prevista: dos modelos de regresión para estimar tiempos de tramo
  según hora/distrito y comparar A* con costo fijo y costo aprendido.
El título no promete tráfico ni prioridades que todavía no existen.

13. SOLUCIÓN DE PROBLEMAS FRECUENTES
"py no se reconoce": probar python --version; si tampoco existe, instalar
Python y abrir de nuevo CMD.
"No suitable Python runtime found": py -3.12 no encuentra esa versión;
instalarla o usar py -m venv .venv con otra compatible.
"No module named streamlit/matplotlib": ejecutar la instalación del paso 4
con .venv\Scripts\python.exe, no con otra instalación de Python.
"requirements.txt no encontrado": CMD está en una carpeta equivocada;
usar dir y abrir la carpeta donde está app.py.
"app.py does not exist": revisar el nombre del archivo y la ruta actual.
"Port 8501 already in use": cerrar la otra sesión o ejecutar:
.venv\Scripts\python.exe -m streamlit run app.py --server.port 8502
Después abrir http://localhost:8502
Error instalando dependencias: comprobar Internet y Python 3.12; copiar
el error completo antes de modificar requirements.txt al azar.
No se ve el repositorio en Streamlit: revisar que usan la cuenta GitHub
correcta y escribir el repositorio manualmente si la lista no lo sugiere.
Error en Cloud: revisar logs, main file path y requirements.txt en la raíz.
Mapa con colores distintos: comprobar .streamlit/config.toml.
Tiempo de A* mayor que BFS: no es un error; en un mapa tan pequeño el costo
extra de la heurística puede pesar más que las expansiones ahorradas.
Base "Sin ruta" tras bloquear un tramo: es el comportamiento esperado.
Base y BFS dan la misma ruta: es posible, y ocurre en el ejemplo principal;
no cambiar los resultados para fabricar una diferencia.
